# ВИЗИТКА — сайт-визитка с приёмом оплаты

Статический сайт на чистом HTML/CSS/JS + маленький Node-сервер для приёма платежей ЮKassa.
Внешних зависимостей нет — `npm install` не нужен.

## Запуск

```bash
node server.js
```

Открыть: http://localhost:3000

Сайт запускается в **мок-режиме**: платёжная страница имитируется самим сервером,
реальных денег нет, ключи и регистрация не нужны. Нажми «Оплатить» на любой услуге —
увидишь фейковую страницу провайдера, где можно принять или отклонить платёж.

> Через `file://` сайт откроется, но оплата работать не будет — ей нужен сервер.
> Это не баг: платёжный ключ нельзя держать в браузере.

## Два режима оплаты

| Режим | Ключи | Что происходит |
|---|---|---|
| `mock` (по умолчанию) | не нужны | фейковая страница на `/mock-pay/…`, вебхук срабатывает локально |
| `live` | нужны | настоящая ЮKassa, деньги настоящие |

Переключается переменной `PAY_MODE`. Если ключи заданы, режим становится `live` сам.

## Боевой режим: ЮKassa

1. Зарегистрироваться на [yookassa.ru](https://yookassa.ru) и пройти модерацию.
2. **Настройки → API-ключи**: скопировать *Shop ID* и *секретный ключ*.
3. Запустить:

```bash
PAY_MODE=live \
YOOKASSA_SHOP_ID=123456 \
YOOKASSA_SECRET_KEY=live_XXXXXXXX \
PUBLIC_URL=https://ваш-домен.ru \
node server.js
```

4. В кабинете добавить уведомление `payment.succeeded` на
   `https://ваш-домен.ru/api/webhook`.

Если статус самозанятого оформлять не хочется, реально принимать деньги не получится —
это требование провайдера, а не сайта. Для разработки и этого хватает.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `PAY_MODE` | `mock` или `live` | `mock`, либо `live` если заданы ключи |
| `PORT` | порт сервера | `3000` |
| `PUBLIC_URL` | публичный адрес (в него провайдер возвращает клиента) | `http://localhost:PORT` |
| `YOOKASSA_SHOP_ID` | Shop ID из кабинета | — |
| `YOOKASSA_SECRET_KEY` | секретный ключ | — |

## Что можно проверять в мок-режиме

- редирект на страницу оплаты и обратно на сайт;
- обработку `?paid=1` (успех) и `?paid=0` (отмена) на фронтенде;
- вебхук и запись в журнал;
- валидацию на сервере: чужая услуга, плохая почта, сумма ниже минимума;
- состояния UI: лоадер, ошибка, блокировка кнопки.

Мок хранит незавершённые платежи в памяти — после перезапуска сервера старые ссылки
на страницу оплаты перестают работать, это ожидаемо.

## Прайс услуг

Файл `data/services.json` — источник правды для минимальных сумм:

```json
[
  { "name": "Лендинг", "price": 45000 }
]
```

Сервер сверяет сумму с этим прайсом, поэтому клиент не может вписать
произвольную цену. Меняете цены здесь — и в `index.html` в `data-price`.

## Заказы

Все платежи пишутся в `data/orders.ndjson` — по строке на событие:

- `created` — платёж создан, ждёт оплаты;
- `paid` — оплата подтверждена;
- `canceled` — платёж отклонён или отменён.

Смотреть в реальном времени:

```bash
tail -f data/orders.ndjson
```

Продакшену это заменяют на нормальное хранилище (Postgres/SQLite) и админку.

## Как это устроено

| Файл | Назначение |
|---|---|
| `server.js` | статика + `POST /api/pay` + `POST /api/webhook` + мок-провайдер |
| `data/services.json` | прайс для серверной проверки |
| `data/orders.ndjson` | журнал платежей |
| `index.html`, `styles.css`, `script.js` | сам сайт |

**Безопасность.** Секретный ключ живёт только в переменных окружения на сервере и
никогда не попадает в браузер. В вебхуке входящим данным не доверяют — статус
вместо них переспрашивается у провайдера по API, иначе поддельное «оплачено»
можно было бы прислать обычным POST. Данные карты сайт не получает вообще.

## Перед публикацией

Контакты, проекты и отзывы **вымышленные** — это демо-контент. Замените на реальные,
подключите отправку обычной формы (`#form` сейчас только показывает тост) и
поставьте сайт на хостинг с HTTPS и поддержкой Node.
